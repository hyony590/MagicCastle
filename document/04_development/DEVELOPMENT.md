# 게임 개발

## 소스 코드와 실행 방법

소스는 [`source/`](../../source) 폴더에 있다. TypeScript, Phaser 3, Vite를 쓴다.

```bash
cd source
npm install
npm run dev        # http://localhost:5173 개발 서버
npm run build      # 타입 검사 후 dist/에 배포용 빌드
npm run check:levels   # 모든 레벨이 실제로 깰 수 있는지 검사
```

| 경로 | 내용 |
| --- | --- |
| `source/src/config.ts` | 화면 크기, 층 높이, 이동·점프·사다리 속도, 낙사 높이, 점수, 보너스 글자 등 조정값 |
| `source/src/levels/` | 레벨 데이터(`level1.ts`~`level10.ts`), 형식(`types.ts`), 데이터 검사(`index.ts`), 통과 가능 여부 검사(`check.ts`) |
| `source/src/scenes/GameScene.ts` | 플레이 로직: 이동, 사다리, 점프, 낙사, 아이템, 상자, 글자, 적, 함정, HUD, 상태 전환 |
| `source/src/scenes/TitleScene.ts`, `EndScene.ts` | 타이틀, 게임 오버·클리어 화면 |

### 개발 중 바로 시작

개발 서버에서는 페이지를 열거나 파일 저장으로 자동 새로고침될 때 타이틀을 건너뛰고 바로 LEVEL 1이 시작된다. 시작 레벨은 `config.ts`의 `DEV_START_LEVEL`로 바꾸고, 0이면 타이틀부터 나온다. 주소 끝에 `?level=3`을 붙이면 그 레벨로 시작한다. 게임 오버 뒤 Enter로 돌아가는 타이틀은 그대로 나온다. 배포 빌드에는 영향이 없다. 자동 시작 때는 첫 키 입력에서 소리가 켜진다(브라우저 자동재생 제한).

### 관리자 기능

개발 서버(`npm run dev`)에서는 항상 켜지고, 배포 빌드에서는 주소 끝에 `?admin`을 붙였을 때만 켜진다. 비밀 장치가 아니라 편의 기능이라 주소를 아는 사람은 누구나 켤 수 있다. 판별 코드는 `source/src/admin.ts`.

| 화면 | 키 | 동작 |
| --- | --- | --- |
| 타이틀 | 숫자키 `1`~`9`, `0` | 해당 레벨에서 새 게임 시작. `0`은 LEVEL 10 |
| 게임 중 | 숫자키 `1`~`9`, `0` | 해당 레벨로 바로 이동. `0`은 LEVEL 10. 점수·생명·모은 글자는 유지 |

없는 레벨 번호는 무시한다. 화면 오른쪽 위에 주황색 `[관리자]` 표시가 나온다.

### 레벨 통과 가능 여부 검사

`npm run check:levels`는 레벨마다 다음을 검사한다. 같은 검사가 개발 서버의 브라우저 콘솔에도 경고로 나온다.

- 발판 모양만으로 시작 위치에서 모든 아이템·글자·상자에 갈 수 있는지. 이동 경로는 같은 구간 걷기, 사다리, 2칸 이하 틈 점프다. 3칸 이상의 넓은 틈은 사다리로 돌아가야 하는 구간으로 볼 뿐 문제가 아니다.
- 불꽃이 사다리·틈 가장자리에 붙어 있어서, 내리거나 착지한 자리에 서기만 해도 닿는지(거리 20px 미만), 아이템과 겹치는지
- 0층(맨 아래 바닥)에 틈이 없는지

몬스터는 검사하지 않는다. 몬스터는 길을 막는 벽이 아니라 타이밍을 맞춰 피하는 대상이라, 층 전체를 도는 몬스터가 사다리 끝이나 틈 앞을 지나가도 정상이다. 실제 난이도와 타이밍은 직접 플레이해서 확인한다.

레벨을 추가하려면 `levels/`에 파일을 만들고 `levels/index.ts`의 `LEVELS` 배열에 넣는다. 사다리나 오브젝트가 발판 밖에 놓이면 개발 서버의 브라우저 콘솔에 경고가 나온다.

## 그레이박스 프로토타입 규칙 (v0.1)

| 항목 | 현재 값 |
| --- | --- |
| 화면 | 768 × 640 플레이 영역(가로 24칸 × 32px) + 하단 두 줄 HUD 52px, 5개 층(층 간격 120px). 레벨 좌표 x는 0~768, 발판 구간은 0~24칸 |
| 시작 위치 | LEVEL 1~9는 0층 x 704(오른쪽 끝 근처)에서 왼쪽을 보고 시작. LEVEL 10은 0층 가운데 |
| 화면 갱신 | 초당 20프레임(`config.ts`의 `FPS`). 옛날 플래시 게임처럼 살짝 끊겨 보이게 했다. 60이면 부드럽다 |
| 이동 | 걷기 190px/초, 사다리 150px/초, 점프 높이 약 33px(체공 약 0.33초, 수평 약 63px). 공중에서는 방향을 바꿀 수 없다(`airControl: false`) |
| 낙사 | 공중 최고점에서 100px 넘게 떨어져 착지하면 사망. 한 층 아래로 떨어지면 사망한다 |
| 생명 | 3번 시도. 사망 시 같은 레벨을 처음부터 다시 시작하고 점수와 모은 글자는 유지 |
| 클리어 | 레벨의 아이템을 모두 모으면 다음 레벨. 적과 상자는 필수 아님 |
| 상자 | 스피드 부츠(8초간 1.5배) 아니면 몬스터 출현. 레벨 데이터에 `contents: 'boots'` 또는 `'enemy'`로 고정할 수 있다. 나온 몬스터는 기본으로 상자 x ± 100px(발판 구간 안)을 순찰하고, `enemy: { range: [0, 768], crossGaps: true }`처럼 쓰면 층 끝에서 끝까지 틈 위도 지나며 순찰한다(LEVEL 1 상자) |
| 글자 | `S`, `T`, `A`, `R`을 모두 모으면 생명 +1 |
| 몬스터 | 키 48px로 점프(33px)보다 커서 뛰어넘을 수 없다. 발판 구간 또는 `range`로 정한 순찰 범위를 좌우로 왕복한다 |
| 아이템 획득 정지 | 기본 아이템을 먹는 순간 플레이어를 포함한 게임 전체가 0.5초 멈췄다가 이어진다(`PICKUP_PAUSE_MS`). 마지막 아이템은 바로 클리어 |
| 불꽃 함정 | 기본은 항상 켜져 있고 높이 16px·폭 12px라 점프로 뛰어넘는다. 레벨 데이터에 `onMs`·`offMs`를 적으면 켜졌다 꺼졌다 한다 |
| 보스전 (LEVEL 10) | 보스 '그림자 성주'가 발판과 상관없이 화면 어디든 날아다닌다(가끔 0.45초 멈추며 눈이 빨개짐). 몸에 닿으면 사망(판정 여유 2px). 층마다 놓인 보석 14개를 모두 모아야 공격이 열린다(HUD `GEM x/14` → `BOSS ■■…`, 열리는 순간 "공격 가능!" 배너, 잠긴 동안 `Z`를 누르면 남은 개수 안내). 죽으면 보석과 잠금이 처음부터 다시. 공격이 열린 뒤 `Z`를 누르면 발밑에서 돌이 곧장 아래로 날아가 발판을 뚫고 떨어진다(0.65초 쿨다운, 사다리·공중에서도 가능). 보스보다 위에서 던져야 맞는다. 7번 맞히면 승리(1회 500점). 속도 110px/초에서 맞을 때마다 +30. 목적지는 30%(맞을 때마다 +6%) 확률로 플레이어 위치이고 이때는 1.3배로 돌진한다. 나머지는 절반씩 층 하나의 발판 바로 위 또는 화면 아무 곳. 머리 위 220px 안에 돌이 보이면 25%(맞을 때마다 +6%) 확률로 옆으로 130px 피한다. 보석을 먹을 때도 0.5초 정지한다. 설정은 `levels/level10.ts`의 `boss`, 로직은 `scenes/BossFight.ts` |
| 난이도 (`DIFFICULTY`) | 몬스터 속도 = 레벨 데이터 값 × 1.35(최고 175, 플레이어 걷기 190보다 느리게 유지). 상자 몬스터 속도 110. 상자 내용물 비율 부츠 2 : 몬스터 3(부츠 40%, 몬스터 60%). 몬스터·불꽃 판정 여유 1px(이전 3px) |
| 레벨 설계 규칙 | 넓은 틈(3칸 이상)은 점프가 아니라 사다리로 돌아가는 구간이다. 몬스터는 뛰어넘을 수 없지만 길을 막는 벽이 아니라 타이밍을 맞춰 피하는 대상이다. 몬스터 속도는 플레이어 걷기(190)보다 느리게 둔다(`DIFFICULTY.enemySpeedCap`) |
| 조작 | ← → 걷기, ↑ ↓ 사다리, Space 점프, Z 돌 던지기(보스전), P / Esc 일시정지, M 소리 켜기/끄기 |
| 소리 | `source/src/audio.ts`에서 Web Audio로 생성. 효과음(점프, 아이템, 글자, 1UP, 상자·부츠·몬스터, 사망, 클리어, 게임 오버, 최종 클리어, 일시정지)과 8마디 반복 배경음악. 음소거 설정은 브라우저에 저장 |
