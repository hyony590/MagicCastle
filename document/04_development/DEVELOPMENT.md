# 게임 개발

## 소스 코드와 실행 방법

소스는 [`source/`](../../source) 폴더에 있다. TypeScript, Phaser 3, Vite를 쓴다.

```bash
cd source
npm install
npm run dev        # http://localhost:5173 개발 서버
npm run build      # 타입 검사 후 dist/에 배포용 빌드
npm run check:levels   # 모든 레벨이 실제로 깰 수 있는지 검사
npm run export:sprites # 코드 그림(art/sprites.ts)을 PNG 파일로 뽑기(이미 있는 파일은 건너뜀)
```

| 경로 | 내용 |
| --- | --- |
| `source/src/config.ts` | 화면 크기, 층 높이, 이동·점프·사다리 속도, 낙사 높이, 점수, 보너스 글자 등 조정값 |
| `source/src/levels/` | 레벨 데이터(`level1.ts`~`level10.ts`), 형식(`types.ts`), 데이터 검사(`index.ts`), 통과 가능 여부 검사(`check.ts`) |
| `source/src/scenes/GameScene.ts` | 플레이 로직: 이동, 사다리, 점프, 낙사, 아이템, 상자, 글자, 적, 함정, HUD, 상태 전환 |
| `source/src/scenes/TitleScene.ts`, `EndScene.ts` | 타이틀, 게임 오버·클리어 화면 |
| `source/src/story/prologue.ts` | 프롤로그 대사·장면 데이터: 화면, 비트(대사 한 번), 연출(cue), 카메라 구도(shot), 표정(face), 장 제목 카드, 화면 전환 방식 |
| `source/src/scenes/PrologueScene.ts` | 프롤로그 화면: 대사창, 얼굴 그림, 목소리, 장 제목 카드, 화면 전환, 검은 띠, 제목 등장, 배경 음악 |
| `source/src/scenes/prologueStage.ts`, `prologueBackdrops.ts` | 프롤로그 무대: 장면별 인물 배치와 연출, 카메라(확대·이동), 배경 그림(마을 아침·해 질 녘·밤, 무대, 성문, 성으로 가는 길) |
| `source/src/art/pngSprites.ts`, `source/src/assets/sprites/` | PNG 그림 불러오기. 같은 이름의 PNG가 있으면 코드 그림 대신 쓴다 |
| `source/src/audio.ts` | 효과음·배경 음악·대사 목소리(음원 파일 없이 Web Audio로 생성) |

### 개발 중 바로 시작

개발 서버에서도 페이지를 열면 시작 화면부터 나온다(`config.ts`의 `DEV_START_LEVEL = 0`). 숫자로 바꾸면 그 레벨에서 바로 시작한다. 주소 끝에 `?level=3`을 붙이면 그 레벨로 시작한다. 게임 오버 뒤 Enter로 돌아가는 타이틀은 그대로 나온다. 배포 빌드에는 영향이 없다. 자동 시작 때는 첫 키 입력에서 소리가 켜진다(브라우저 자동재생 제한).

프롤로그는 주소 끝에 `?prologue=화면.대사`를 붙이면 그 자리부터 열린다(번호는 1부터). 예: `?prologue=4`는 4번째 화면, `?prologue=7.2`는 7번째 화면의 2번째 대사, `?prologue`만 쓰면 첫 화면. 중간 대사로 열어도 앞 대사의 연출은 적용된 상태로 시작한다. [다음]·[이전]을 누르면 주소의 번호도 따라 바뀌어서, 대사나 그림을 고친 뒤 새로고침하면 보던 자리로 돌아온다. 프롤로그를 마치고 게임으로 넘어가면 주소에서 지워진다. 없는 번호는 가장 가까운 화면으로 맞춘다. 코드는 `admin.ts`의 `devPrologueStart`·`setPrologueUrl`.

### 그림을 PNG로 바꾸기

`source/src/assets/sprites/<키>.png`가 있으면 게임이 코드 그림(`art/sprites.ts`) 대신 그 파일을 쓴다. 파일을 지우면 코드 그림으로 돌아간다. 그림은 원본 크기(예: 모찌 14×20)로 그리면 2배로 키워 쓰고, 화면 크기(28×40)로 그리면 그대로 쓴다. 다른 크기면 콘솔에 경고가 나온다. 크기 표와 그리는 규칙은 [sprites/README.md](../../source/src/assets/sprites/README.md).

`npm run export:sprites`는 코드 그림을 PNG로 뽑는다. 이미 있는 파일(직접 고친 그림)은 덮어쓰지 않는다. 전부 다시 뽑으려면 `npm run export:sprites -- --force`. 프롤로그 인물·배경 그림은 아직 코드 그림만 있다.

### 관리자 기능

개발 서버(`npm run dev`)에서는 항상 켜지고, 배포 빌드에서는 주소 끝에 `?admin`을 붙였을 때만 켜진다. 비밀 장치가 아니라 편의 기능이라 주소를 아는 사람은 누구나 켤 수 있다. 판별 코드는 `source/src/admin.ts`.

| 화면 | 키 | 동작 |
| --- | --- | --- |
| 타이틀 | 숫자키 `1`~`9`, `0` | 해당 레벨에서 새 게임 시작. `0`은 LEVEL 10 |
| 게임 중 | 숫자키 `1`~`9`, `0` | 해당 레벨로 바로 이동. `0`은 LEVEL 10. 점수·생명·모은 글자는 유지 |

없는 레벨 번호는 무시한다. 화면 오른쪽 위에 주황색 `[관리자]` 표시가 나온다.

### 레벨 통과 가능 여부 검사

`npm run check:levels`는 레벨마다 다음을 검사한다. 같은 검사가 개발 서버의 브라우저 콘솔에도 경고로 나온다.

- 발판 모양만으로 시작 위치에서 모든 아이템·글자·상자에 갈 수 있는지. 이동 경로는 같은 구간 걷기, 사다리, 2칸 이하 틈 점프다. 3칸 이상의 넓은 틈은 사다리로 돌아가야 하는 구간으로 볼 뿐 문제가 아니다.
- 불꽃이 사다리·틈 가장자리에 붙어 있어서, 내리거나 착지한 자리에 서기만 해도 닿는지(거리 20px 미만), 아이템과 겹치는지
- 0층(맨 아래 바닥)에 틈이 없는지

몬스터는 검사하지 않는다. 몬스터는 길을 막는 벽이 아니라 타이밍을 맞춰 피하는 대상이라, 층 전체를 도는 몬스터가 사다리 끝이나 틈 앞을 지나가도 정상이다. 실제 난이도와 타이밍은 직접 플레이해서 확인한다.

### 자동 플레이 봇

시작 화면의 **[자동 플레이 보기]** 버튼을 누르면 봇이 LEVEL 1부터 엔딩까지 플레이한다. 무적이나 순간이동 없이 사람과 같은 키 입력(방향키, Space, Z)만 쓴다. 화면 위 패널에서 속도(1·2·4·8배)를 바꿀 수 있고, **[멈추고 직접 하기]**를 누르면 그 자리에서 사람이 이어서 플레이한다. 끝나면 결과(성공/게임 오버, 죽은 횟수, 걸린 시간)가 패널에 나온다. 코드는 `source/src/autoplay.ts`.

- 길 찾기: 발판 구간을 점, 사다리와 2칸 이하 틈을 선으로 이어 가장 가까운 재료·글자부터 간다.
- 몬스터: 앞으로의 위치를 계산해, 가는 동안 부딪히지 않고 도착한 뒤에도 사다리(또는 틈을 건너 사다리)로 피할 수 있을 때만 간다. 아니면 기다리거나 사다리 중간으로 숨는다. 30초 넘게 진전이 없으면 조금 대담해진다.
- 불꽃: 점프 높이와 속도로 계산한 거리(보통 27~35px, 부츠 33~58px)에서 뛰어넘는다.
- 보스: 마녀가 지금 날아가는 방향만 보고(다음 목적지는 무작위라 알 수 없음) 0.75초 앞까지 가만히·왼쪽·오른쪽·사다리 위아래를 시험해 가장 안전한 행동을 고른다. 보석을 다 모으면 맨 위층에서 마녀를 따라가다 반죽이 떨어질 때 맞을 것 같으면 Z.

개발 서버 콘솔에서는 `__autoplay(레벨, 속도)`로 화면을 기다리지 않고 빠르게 돌릴 수 있다(레벨은 0부터, 속도 0 = 최대한 빠르게). 결과는 `__bot.report()`.

레벨을 추가하려면 `levels/`에 파일을 만들고 `levels/index.ts`의 `LEVELS` 배열에 넣는다. 사다리나 오브젝트가 발판 밖에 놓이면 개발 서버의 브라우저 콘솔에 경고가 나온다.

## 그레이박스 프로토타입 규칙 (v0.1)

| 항목 | 현재 값 |
| --- | --- |
| 화면 | 768 × 640 플레이 영역(가로 24칸 × 32px) + 하단 두 줄 HUD 52px, 5개 층(층 간격 120px). 레벨 좌표 x는 0~768, 발판 구간은 0~24칸 |
| 시작 위치 | LEVEL 1~9는 0층 x 704(오른쪽 끝 근처)에서 왼쪽을 보고 시작. LEVEL 10은 0층 가운데 |
| 화면 갱신 | 초당 20프레임(`config.ts`의 `FPS`). 옛날 플래시 게임처럼 살짝 끊겨 보이게 했다. 60이면 부드럽다 |
| 이동 | 걷기 190px/초, 사다리 150px/초, 점프 높이 약 37px(체공 약 0.35초, 수평 약 67px, 불꽃은 21~46px 앞에서 뛰면 넘음). 공중에서는 방향을 바꿀 수 없다(`airControl: false`) |
| 낙사 | 공중 최고점에서 100px 넘게 떨어져 착지하면 사망. 한 층 아래로 떨어지면 사망한다 |
| 생명 | 3번 시도. 사망 시 같은 레벨의 시작 자리에서 다시 하고, 그 레벨에서 이미 먹은 재료(보스전은 보석)·점수·모은 글자는 유지. 보석을 다 모은 뒤 기절하면 보스전은 처음부터 공격 가능하고, 깎아 둔 마녀 HP(와 그만큼 빨라진 속도)도 유지. 연 상자도 열린 채로 남고, 나온 것도 그대로(운동화는 상자 위에 다시 놓임 — 신고 있다가 기절했으면 벗겨져서 다시 상자 위로, 몬스터는 같은 종류가 상자 자리에서 다시 출발). 레벨 몬스터는 처음 자리로. 게임 오버면 새 판 |
| 클리어 | 레벨의 아이템을 모두 모으면 다음 레벨. 적과 상자는 필수 아님 |
| 상자 | 스피드 부츠(걷기 1.5배, 시간 제한 없음, 죽거나 다음 레벨로 넘어가면 사라짐) 아니면 몬스터 출현. 부츠는 바로 신지 않고 열린 상자 위에 놓인다. 열린 뒤 0.6초가 지나고 운동화에서 비켜난 다음 다시 밟아야 신는다(걸어서 지나가면 그대로 둠). 레벨 데이터에 `contents: 'boots'` 또는 `'enemy'`로 고정할 수 있다. 나온 몬스터는 기본으로 상자 x ± 100px(발판 구간 안)을 순찰하고, `enemy: { range: [0, 768], crossGaps: true }`처럼 쓰면 층 끝에서 끝까지 틈 위도 지나며 순찰한다(LEVEL 1 상자) |
| 글자 | `B` `A` `K` `I` `N` `G`(BAKING) 글자 쿠키가 레벨 2~7에 하나씩. 여섯 글자를 모두 모으면 생명 +1(모은 글자는 기절해도 유지, 완성하면 비워짐). HUD 오른쪽 아래 작은 쿠키 6개 중 모은 글자가 색으로 켜진다 |
| 몬스터 | 키 48px로 점프(37px)보다 커서 뛰어넘을 수 없다. 발판 구간 또는 `range`로 정한 순찰 범위를 좌우로 왕복한다 |
| 아이템 획득 정지 | 없음(`PICKUP_PAUSE_MS = 0`). 값을 넣으면 그 시간(ms)만큼 게임 전체가 멈춘다 |
| 불꽃 함정 | 기본은 항상 켜져 있고 판정은 그림의 파란 몸통 아래쪽(높이 12px·폭 8px, 노란 끝은 안전)이라 점프로 뛰어넘는다. 레벨 데이터에 `onMs`·`offMs`를 적으면 켜졌다 꺼졌다 한다 |
| 보스전 (LEVEL 10) | 보스(마녀 쿠르르, 화면 128×128·판정 96×96)가 발판과 상관없이 화면 어디든 날아다닌다(가끔 0.45초 멈추며 눈이 빨개짐). 몸에 닿으면 사망(판정 여유 2px). 층마다 놓인 보석 14개를 모두 모아야 공격이 열린다(HUD `GEM x/14` → `BOSS ■■…`, 열리는 순간 "공격 가능!" 배너, 잠긴 동안 `Z`를 누르면 남은 개수 안내). 죽으면 보석과 잠금이 처음부터 다시. 공격이 열린 뒤 `Z`를 누르면 발밑에서 돌이 곧장 아래로 날아가 발판을 뚫고 떨어진다(0.65초 쿨다운, 사다리·공중에서도 가능). 보스보다 위에서 던져야 맞는다. 5번 맞히면 승리(1회 500점). 속도 110px/초에서 맞을 때마다 +30. 목적지는 5% 확률로 플레이어 위치이고 이때는 1.3배로 돌진한다. 나머지는 절반씩 층 하나의 발판 바로 위 또는 화면 아무 곳. 돌을 피하지 않는다(`dodgeChance: 0`). 보석을 먹을 때도 0.5초 정지한다. 설정은 `levels/level10.ts`의 `boss`, 로직은 `scenes/BossFight.ts` |
| 난이도 (`DIFFICULTY`) | 몬스터 속도 = 레벨 데이터 값 × 1.35(최고 175, 플레이어 걷기 190보다 느리게 유지). 상자 몬스터 속도 110. 상자 내용물 비율 부츠 2 : 몬스터 3(부츠 40%, 몬스터 60%). 몬스터·불꽃 판정 여유 1px(이전 3px) |
| 레벨 설계 규칙 | 넓은 틈(3칸 이상)은 점프가 아니라 사다리로 돌아가는 구간이다. 몬스터는 뛰어넘을 수 없지만 길을 막는 벽이 아니라 타이밍을 맞춰 피하는 대상이다. 몬스터 속도는 플레이어 걷기(190)보다 느리게 둔다(`DIFFICULTY.enemySpeedCap`) |
