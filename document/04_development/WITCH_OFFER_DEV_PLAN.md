# 마녀의 제안 개발 계획

> 상태: **계획 단계**. 아직 코드를 고치지 않았다. 사용자가 "시작하자"라고 하면 1단계부터 진행한다.
> 2부의 이야기와 분위기는 [PART2_HORROR.md](../01_game-planning/PART2_HORROR.md)가 기준이다. 이 문서는 **만드는 순서와 기술 방향**을 정한다.

## 1. 목표

1부(모찌의 마녀 부엌)에서 생명을 모두 잃으면 게임 오버 화면 대신 **마녀의 제안 화면**이 나온다. 플레이어는 두 버튼 중 하나를 고른다.

- **처음부터 다시 시작**: LEVEL 1부터 새 판을 시작한다. 프롤로그는 다시 보여 주지 않는다.
- **마녀의 제안 받아들이기**: 새로운 게임 환경(2부, 쯔꾸르식 3인칭 공포)으로 들어간다.

## 2. 확정된 결정

| 항목 | 결정 | 출처 |
| --- | --- | --- |
| 게임 오버 화면 | 버튼 2개: [처음부터 다시 시작] [마녀의 제안 받아들이기] | 사용자 답변 |
| 다시 시작 | LEVEL 1, 새 판(`newRun()`). 생명 3, 점수 0, 모은 글자 비움. 프롤로그 없음 | 사용자 답변 |
| 받아들이기 | 새 게임 환경으로 진입. 2부는 쯔꾸르식 | 사용자 답변 |
| 2부 시점 | 위에서 비스듬히 내려다보는 3인칭. 모찌가 칸 단위로 걸어 다닌다 | PART2_HORROR.md |
| 2부 분량(첫 버전) | 방 4~5개, 퍼즐 2~3개, 추격 1번, 엔딩 1개(10~15분) | PART2_HORROR.md |

2부 스토리(후보 A·B·C)는 아직 정하지 않았다. 시스템을 먼저 만들고, 맵과 대사는 스토리가 정해진 뒤에 쓴다.

## 3. 화면 흐름

```
1부 LEVEL 1~10
  └ 생명 0 ─ GameScene.die()
        ▼
  [마녀의 제안 화면: WitchOffer]
        ├ [처음부터 다시 시작] ─────────→ Game (LEVEL 1, newRun)
        └ [마녀의 제안 받아들이기] ─ 전환 연출 ─→ Part2 (2부 첫 방)
```

- 1부를 **다 깼을 때**의 흐름은 이번 결정에 없다. 지금처럼 성공 엔딩(EndScene victory)을 그대로 둔다.
- 기존 게임 오버 화면(EndScene의 gameover, "ENTER로 타이틀")은 제안 화면으로 대체된다. 남길지는 열린 질문 6번.

## 4. 1단계: 마녀의 제안 화면과 다시 시작

**목표**: 생명을 잃으면 제안 화면이 뜨고, 두 버튼이 모두 동작한다.

- 새 씬 `WitchOfferScene` (`source/src/scenes/WitchOfferScene.ts`), `main.ts`에 등록.
- 화면: 어두운 식탁 배경, 마녀 쿠르르 그림(보스 그림 재사용 가능), 프롤로그 대사창 스타일 재사용.
- 대사: 1~2줄, 한 글자씩 출력. 문구는 placeholder로 두고 나중에 확정.
- 버튼 두 개. 기본 선택은 [처음부터 다시 시작]. ←→로 고르고 Enter, 마우스·터치도 지원.
- `GameScene.die()`의 게임 오버 분기를 `WitchOffer`로 바꾼다. 생명이 남아 있을 때의 재시작은 그대로다.
- **검증**: 생명 0에서 제안 화면이 뜬다 · [다시 시작]을 누르면 LEVEL 1, 생명 3, 점수 0 · 키보드·마우스 모두 동작.

## 5. 2단계: 2부 진입 전환 연출

- [받아들이기]를 누르면 화면이 지지직 깨진다: 노이즈, 색 어긋남, 음악이 일그러졌다가 끊김.
- 길이 2초 안팎. 연출 중에는 입력을 막는다.
- 효과음 추가 필요(`audio.ts`).
- **검증**: 연출이 끝나면 2부 씬으로 넘어간다 · 연출 중 키를 눌러도 두 번 넘어가지 않는다.

## 6. 3단계: 2부 게임 환경 프로토타입 (쯔꾸르식)

**목표**: 방 한 개에서 모찌가 걸어 다니고, 벽에 막히고, 어둠 속에서 주변만 보인다.

| 항목 | 방향 |
| --- | --- |
| 이동 | 4방향, 32px 칸 단위. 한 칸 이동은 약 0.15초 트윈. 이동 중 입력 큐 1칸 |
| 충돌 | 칸마다 통과 가능 여부. 오브젝트(문, 상자, 인물)도 칸에 놓는다 |
| 맵 데이터 | 1부 레벨처럼 TS 파일로 쓴다. 문자 그리드 + 범례 예: `#` 벽, `.` 바닥, `D` 문, `K` 열쇠, `N` 인물, `E` 추격자 시작 |
| 어둠 | 플레이어 주변만 밝힌다. 원형 빛 텍스처를 블렌드 모드로 씌운다. 촛불을 얻으면 반경이 커진다 |
| 대화 | 프롤로그 패널의 타이핑·말풍선 로직을 `ui/dialogue.ts`로 빼서 두 곳에서 쓴다. 2지 선택 UI 추가 |
| 조사 | 결정 키 + 바라보는 칸의 오브젝트 → 대사창 |
| 소지품 | 간단한 목록 HUD. 이름과 작은 아이콘 |
| 조작 | 방향키 이동, Enter·Space 조사와 확인, Esc 메뉴(일시정지), M 소리 |
| 저장 | v1은 메모리에만 둔다. 새로고침하면 처음부터 |

- 새 씬 `Part2Scene` (`source/src/scenes/Part2Scene.ts`), 맵 데이터는 `source/src/part2/`.
- **검증**: 벽에 막힌다 · 어둠 반경이 플레이어를 따라간다 · 조사 대사가 뜬다 · 맵 검사 스크립트가 통과한다(7단계와 같이 만든다).

## 7. 4단계: 맵 검사 스크립트

1부의 `check:levels`처럼, 맵이 잘못 만들어졌는지 콘솔에서 검사한다.

- 시작 칸에서 엔딩 칸까지 도달 가능한가
- 열쇠가 그 열쇠가 여는 문보다 앞에 있는가
- 추격자가 시작 칸을 막고 있지 않은가
- 명령: `npm run check:maps` (`source/scripts/check-maps.ts`, `package.json`에 추가)

## 8. 5단계: 대화·퍼즐 연결

- 퍼즐 2~3개: 열쇠 찾기, 쪽지 조합, 촛불 얻기 같은 단순한 것부터.
- 퍼즐 조건이 맞으면 문이 열리고 대사가 바뀌는 방식.
- 스토리가 정해지기 전에는 대사를 `placeholder`로 두고, 나중에 교체한다.

## 9. 6단계: 추격과 깜짝 연출

- 추격자는 칸 단위 최단 경로(BFS)로 플레이어를 쫓는다. 속도는 플레이어보다 조금 느리게 해서 타이밍으로 피할 수 있게 한다.
- 닿으면 붙잡힌다 → 그 방의 입구(체크포인트)에서 다시 시작한다.
- 깜짝 연출: 화면 흔들림(`cameras.main.shake`), 얼굴 그림 한 장, 큰 효과음.
- **검증**: 추격자가 벽에 막혀 멈추지 않는다 · 붙잡힌 뒤 체크포인트에서 다시 시작한다.

## 10. 7단계: 방 4~5개와 엔딩

- 방 구성과 퍼즐은 스토리 확정 후 작성한다.
- 엔딩 화면 뒤에는 [타이틀로] 또는 [1부 처음부터]로 간다(열린 질문 5번).
- 그림과 소리는 기존 워크플로를 따른다. 그림은 PNG로 뽑아 고치는 방식(`export:sprites`)과 같은 방식을 쓴다.
  - 필요한 그림: 어두운 바닥·벽·문 타일, 모찌 뒷모습·옆모습, 마녀 전신, 소지품 아이콘, 방 배경.
  - 필요한 소리: 2부 드론 음악, 발소리, 문 열리는 소리, 추격 소리, 전환 효과음.
- 목록은 [ASSET_LIST.md](../03_game-assets/ASSET_LIST.md)에 추가한다.

## 12. 검증 방법(모든 단계 공통)

- `npm run typecheck`, `npm run build`, `npm run check:levels`는 매 단계 통과해야 한다.
- 2부부터는 `npm run check:maps`도 통과해야 한다.
- 브라우저 미리보기로 각 단계의 검증 항목을 확인하고, 스크린샷으로 남긴다.
- 자동 플레이 봇(`source/src/autoplay.ts`)은 게임 오버 결과(`gameover`)를 기록한다. 제안 화면이 생긴 뒤에도 봇이 멈추지 않는지 확인한다.

## 13. 열린 질문(사용자 결정 필요)

1. 2부 스토리는 후보 A·B·C 중 무엇인가? ([PART2_HORROR.md](../01_game-planning/PART2_HORROR.md))
2. 1부를 **다 깼을 때**도 같은 제안을 할까? 지금은 성공 엔딩 그대로다.
3. 제안을 받아들이면 점수와 모은 글자를 가져갈까, 2부는 빈 상태로 시작할까?
4. 2부에서 붙잡히면 방 입구에서 다시 시작하는 것이 맞을까?
5. 2부 엔딩 뒤에는 타이틀로 갈까, 1부 처음으로 갈까?
6. 기존 게임 오버 화면(EndScene의 "ENTER로 타이틀")은 지울까, 남겨 둘까?
7. [PART2_HORROR.md](../01_game-planning/PART2_HORROR.md)의 "[이어서 하기]"는 이번 결정(다시 시작 = LEVEL 1)으로 바꿀까?
8. 2부 이동은 칸 단위(추천)로 할까, 부드러운 자유 이동으로 할까?

## 14. 위험

- 어둠 효과와 칸 이동을 저사양 브라우저에서 부드럽게 돌릴 수 있는지 확인이 필요하다.
- 스토리가 정해지기 전에 맵을 만들면 낭비가 생긴다. 그래서 시스템(3단계)을 먼저 만든다.
- 1부의 글꼴·음악 로딩 순서가 2부 전환에서 깨질 수 있다.
- 자동 플레이 봇과 검사 스크립트가 새 씬과 충돌할 수 있다.
